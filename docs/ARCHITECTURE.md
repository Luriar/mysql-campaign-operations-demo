# 설계 및 데이터 보호 원칙

이 문서는 실제 코드가 아닌 공개용 요약입니다. 서비스 계정, 클라이언트 식별자, 내부 URL, DB 접속정보, 스크래핑 선택자와 회사 원본 파일을 담지 않습니다.

## 업무 흐름

Excel/입력 데이터 → 중복 및 무결성 점검 → 백업 후 DB 수정 → 발송 시스템 대상 조회 → 결과 및 회신에 따른 갱신. 회사 DB의 실제 테이블명, 컬럼명, 운영 규모는 의도적으로 제외했습니다.

## 실무 경험과 데모의 차이

- **실무 경험:** 대상 목록 추가, 회신 대상 제외, 메시지 수정에 필요한 Python 및 SQL 스크립트를 작성했습니다.
- **예시 구현:** 가상 대상의 중복 등록과 응답 대상 제외, 트랜잭션 처리 및 남은 대상 조회를 SQLite로 구현합니다.
- **비공개:** 회사 업무 시스템에 종속된 세부 구현, 고객 및 사용자 데이터, 계약/운영 정보
- **미확정 항목:** 미측정 성능 개선률, 세부 배포 이력, 회사 측 승인 범위

## 개선 및 품질 관점

실무에서 발생했던 데이터 중복, 오류 추적, 관리 편의성과 수동 확인의 필요성 같은 문제를 일반화하여 설명합니다. 수치와 성과는 확인된 근거가 없는 경우 기재하지 않습니다.
